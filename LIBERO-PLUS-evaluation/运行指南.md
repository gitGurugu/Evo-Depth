# LIBERO-PLUS 评测

LIBERO-PLUS 是在 LIBERO 上加了 7 类扰动的鲁棒性评测。任务和仿真来自 [LIBERO-plus](https://github.com/sylvestf/LIBERO-plus)，策略仍用 Evo-Depth 的 LIBERO 权重。每个任务默认 1 条 episode。

扰动类别：`camera`、`robot`、`language`、`light`、`background`、`noise`、`layout`。

不要动 `.venv-libero` 和 `~/.libero/config.yaml`。PLUS 用单独的 `.venv-libero-plus` 和 `~/.libero-plus`。7 路 server 用 9000–9006。

## 前置工作

### 1. 拉取并安装 LIBERO-plus

不要用 `pip install git+https://...` 代替 clone。Client 要读这份目录里的 `LIBERO-plus/libero/libero/benchmark/task_classification.json`，只装进 site-packages 对不上路径。

```bash
cd /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation
git clone https://gitclone.com/github.com/sylvestf/LIBERO-plus.git LIBERO-plus
```

装进新建的 `.venv-libero-plus`。不要装进 `.venv-libero`，那会换掉正在跑的 LIBERO 所用的包。

### 2. Client 环境

```bash
cd /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation
uv venv --python 3.8.13 .venv-libero-plus
source .venv-libero-plus/bin/activate
cd LIBERO-plus
uv pip install -r requirements.txt
uv pip install torch==1.11.0+cu113 torchvision==0.12.0+cu113 torchaudio==0.11.0 --extra-index-url https://download.pytorch.org/whl/cu113
uv pip install -e .
uv pip install -r extra_requirements.txt
uv pip install websockets imageio
```

官方还要求这些系统库，缺了再装：

```bash
sudo apt-get install -y libexpat1 libfontconfig1-dev libpython3-stdlib libmagickwand-dev
```



### 3. 资源包

Hugging Face 上只有一个 6.4 GB 的 `assets.zip`，没有散装文件，不能直接下到 `assets/`。压缩包里已经有一层 `assets/`，解压到上一级 `libero/libero`。解压进 `assets/` 会变成 `assets/assets/`。

```bash
export HF_ENDPOINT=https://hf-mirror.com
hf download Sylvest/LIBERO-plus --repo-type dataset --local-dir /home/kjl/checkpoint/libero-plus-assets --include "assets.zip"
unzip /home/kjl/checkpoint/libero-plus-assets/assets.zip \
  -d /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/libero
```

解压完应有 `LIBERO-plus/libero/libero/assets/textures`。

### 4. 单独的 LIBERO 配置

`get_libero_path()` 每次从配置文件读 bddl、init state 和 assets 的路径。默认文件是 `~/.libero/config.yaml`，正在跑的 LIBERO 也读它。PLUS 改用 `~/.libero-plus/config.yaml`，启动时用 `LIBERO_CONFIG_PATH` 指过去。`test_libero_plus.sh` 已经会导出这个变量。

```bash
mkdir -p /home/kjl/.libero-plus
cat > /home/kjl/.libero-plus/config.yaml << 'EOF'
benchmark_root: /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/libero
bddl_files: /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/libero/bddl_files
init_states: /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/libero/init_files
datasets: /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/datasets
assets: /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/LIBERO-plus/libero/libero/assets
EOF
```



### 5. 权重

不用新权重。suite 和 server 的 `EVO_DEPTH_CKPT_DIR` 必须一致。


| suite          | 权重                                    |
| -------------- | ------------------------------------- |
| libero_spatial | `/home/kjl/checkpoint/libero_spatial` |
| libero_goal    | `/home/kjl/checkpoint/libero_goal`    |
| libero_object  | `/home/kjl/checkpoint/libero_object`  |
| libero_10      | `/home/kjl/checkpoint/libero_10`      |


同一个 server 上挂多个 client 不会并行。每个 suite 开 7 个 server，同一份权重，一个端口一个类别。0 号卡放 4 路（9000–9003），1 号卡放 3 路（9004–9006）。先贴 server，7 个日志都出现 `Evo_depth server running` 后再贴 client。换 suite 时下一段 server 会先停掉上一批。停进程只杀 `evo_plus_pids` 里的 PID，不要 `pkill`。


| 端口   | 卡     | 类别         |
| ---- | ----- | ---------- |
| 9000 | GPU 0 | camera     |
| 9001 | GPU 0 | robot      |
| 9002 | GPU 0 | language   |
| 9003 | GPU 0 | light      |
| 9004 | GPU 1 | background |
| 9005 | GPU 1 | noise      |
| 9006 | GPU 1 | layout     |


结果在 `logs/plus_<suite>_<类别>/log.txt`。

## 冒烟

只开 1 个 server，跑 `libero_spatial` 的 `camera`。日志出现 `Evo_depth server running at ws://0.0.0.0:9000` 后再贴 client。

```bash
source /home/kjl/Evo-Depth/Evo_depth/.venv/bin/activate
cd /home/kjl/Evo-Depth/Evo_depth
kill $(cat /home/kjl/evo_plus_pids) 2>/dev/null || true
rm -f /home/kjl/evo_plus_pids
export HF_ENDPOINT=https://hf-mirror.com
export CUDA_VISIBLE_DEVICES=0
export EVO_DEPTH_CKPT_DIR=/home/kjl/checkpoint/libero_spatial
export EVO_DEPTH_SERVER_PORT=9000
nohup python scripts/Evo_depth_server.py > /home/kjl/evo_server_plus_9000.log 2>&1 &
echo $! > /home/kjl/evo_plus_pids
tail -f /home/kjl/evo_server_plus_9000.log
```

```bash
source /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation/.venv-libero-plus/bin/activate
cd /home/kjl/Evo-Depth/LIBERO-PLUS-evaluation
bash ./test_libero_plus.sh ./logs/plus_smoke_spatial_camera libero_spatial camera ws://127.0.0.1:9000
```

Client 能打出 `Start task suite libero_spatial` 并且开始跑第一条任务，环境和资源就是齐的。结果在 `logs/plus_smoke_spatial_camera/log.txt`。
